# Decisions

Judgment calls made while building Memory Grove, and why. Append to this; don't rewrite history.

## Licensing

- **No separate asset licences upstream.** Checked `reference/memory-forest` for a per-asset
  licence (image folders, fonts) separate from the repo-root MIT `LICENSE`. There is none —
  one MIT licence covers the repository. Regardless, Memory Grove copies no upstream asset;
  every pixel is generated by Memory Grove's own code. See `THIRD_PARTY_NOTICES.md`.

## Data layer (Anki → RemNote)

- **Pond threshold: 14 days, not the original's 7.** The brief explicitly asks for "gaps of
  2+ weeks"; the original's own threshold is 7 days (`BREAK_DAYS` in `forest_data.py`).
  Followed the brief, made it a setting (`DEFAULT_BREAK_DAYS` in `src/data/forest.ts`), and
  recorded the discrepancy in `reference/NOTES.md`.
- **Strength is derived from the scheduled interval, not read from FSRS stability.** RemNote
  exposes no stability or decay. `nextRepetitionTime - lastRepetitionTime` is the scheduler's
  own chosen gap and is monotone with stability on the same scale, so the original's day
  thresholds (21/180/365) carry over unchanged. Full reasoning in `reference/REMNOTE_API.md`
  §2.1.
- **No suspension flag, no leech tag.** Worked around with an "effectively inactive" heuristic
  (overdue by more than a year) and a leech heuristic from `VIEWED_AS_LEECH` scores. Neither
  is load-bearing — see §2.3 and §2.4 of the API doc.
- **Weather provider: Open-Meteo, not MET Norway + Photon.** The brief names Open-Meteo
  explicitly; it also conveniently combines geocoding and forecast in one account-less API,
  where the original needed two.

## Ecosystem health (new feature)

- **Grace is a budget, not a per-run allowance.** A first draft gave `graceDays` free misses
  at the *start* of each run, which meant a user who skipped every third day forever paid
  nothing, ever — caught by a monotonicity test (`health.test.ts`). Replaced with a budget
  that studying replenishes over `graceRefillDays`. A pattern of misses now drains the budget
  faster than it refills, while an isolated miss after a good run still costs nothing.
- **The reported score is a 7-day trailing mean of the simulation, not its last value.**
  Reading the final day alone made the score lurch with the day of the week for a
  weekday-only studier (100 on a Thursday check, visibly lower on a Monday) for identical
  habits. Averaging answers "how have things been lately", which is the actual question.

## Study calendar

- **Semester preset dates are approximate by construction, not by omission.** Only the parts
  that are exactly computable — Easter (the Gregorian computus), and weekday-anchored
  holidays — are computed. Everything else (semester start/end, mid-semester break length) is
  a typical shape, labelled as approximate in the settings UI, and fully editable. No specific
  university's calendar is claimed as fact anywhere.
- **Queensland Ekka holiday approximated as the second Wednesday of August.** It is gazetted
  per year and applies to the Brisbane area only; the real date varies. Documented in the
  function's own comment in `src/data/schedulePresets.ts`, and the part-day Christmas Eve
  holiday is left out entirely rather than approximated as a full day.

## Rendering — the low-resolution buffer fix

- **The scene was drawn straight onto the full device-resolution canvas, not onto a
  low-resolution buffer scaled up.** `reference/NOTES.md`'s own research said the original
  draws "one low-resolution canvas, scaled up," but the first implementation of
  `scene.ts` didn't actually do that: individual sprites were drawn as `k`-pixel blocks
  (genuinely blocky), but the sky, sun and ground used `CanvasGradient` and `ellipse()`
  calls straight against the full canvas, which anti-alias regardless of how the sprites
  next to them are scaled. The user loaded it in RemNote and immediately flagged it as
  looking nothing like pixel art — correctly. Fixed by rendering the *whole* frame
  (sky, ground, water, every sprite) onto a ~220px-wide offscreen canvas and blitting that
  up in one `drawImage` call with smoothing off, which is what actually forces every
  element through the same blocky upscale. Also replaced the sky/ground `CanvasGradient`
  fills with Bayer-dithered two-tone bands (closer to the original's dithering, and
  incapable of smooth-gradient blur by construction), and gave the sun/moon an actual
  hard-edged disc — the earlier version drew only the soft halo glow, with no bright core
  at all, which read as a diffuse blur.
- **`layout.zoom` was computed but never applied.** `layoutGrove` correctly scales a young
  grove up to 1.8x so a handful of plants still read as distinct trees, but `scene.ts`
  never multiplied a placed item's draw scale by it — caught from the same screenshot: a
  10-plant grove rendered as a thin, indistinct smudge rather than a few large plants.
  Fixed alongside the rendering buffer change.

## The sprite-scale bug — the root cause of "doesn't look like Memory Forest"

- **`buildToneMap` generated a fixed, stage-only tone map, and the caller tried to reach
  the real target size by scaling it up by an *integer* factor
  (`round(targetHeight / tonemap.height)`).** For a Sapling or Young plant, the fixed tone
  map was already close to the target height, so that ratio rounded to 1 however much the
  depth/zoom scaling asked for. Concretely: a Sapling's base tone map is 10 engine-pixels
  tall; even at the grove-zoom cap of 1.8x, the requested height only reached ~14px, and
  `round(14/10) = 1` — the exact same as `round(8/10) = 1` with no zoom at all. The
  "zoom in when the grove is small" mechanic, and ordinary near/far depth scaling, were
  both silently no-ops for most of a grove's life. This is what made a real, sparse
  RemNote account's grove read as a field of tiny indistinct smudges rather than a few
  clear trees — not a style problem, an architecture bug.
- Fixed by building the tone map at the real target size directly: `buildToneMap(plant,
  form, scale)` now multiplies the crown/trunk height by `scale` before generating
  anything, so depth and zoom are baked into the sprite's own resolution rather than
  applied as an ineffective integer post-scale. `scene.ts` no longer computes a separate
  `spriteK` at all. The seeded RNG that places each crown's blobs is still keyed only by
  the plant's own seed (not by `scale`), so a given plant's silhouette stays stable as its
  size changes continuously with depth — only its resolution changes, not its shape.
- Also raised `ENGINE_WIDTH` from 220 to 300 (the internal drawing-buffer width everything
  is rendered at before the final nearest-neighbour blit) for a finer pixel grain at the
  widths the plugin actually renders at in RemNote, per separate user feedback that the
  whole scene — not just trees — read as too blocky. A plant's size in engine pixels
  (`STAGE_HEIGHT`) didn't need to change alongside this: distance from camera decides how
  big something looks, not the buffer's own resolution.
- Verified by rendering the exact fixture that matches the user's real account (a handful
  of young plants, mostly Sapling/Young stage) before and after, and separately confirmed
  via the screenshot harness that a dense (veteran) grove's crown texture, trunks and
  species diversity all read far more clearly at the finer buffer resolution.

## Region packs (new feature)

- **Art is entirely procedural — no image or sprite assets anywhere, for any region.**
  Hand-drawing consistent pixel art for over 140 species across 11 regions could not be done
  to a uniform standard, and the original's own tree rendering (`web/engines/pixel/trees.js`)
  is itself procedural — tone map first, palette second. Creatures follow the same discipline:
  a `BodyPlan` (lengths, angles, named parts) plus a `Palette`, rendered by one of eight shared
  body-plan routines (`src/regions/types.ts`). This is also what makes the pack-validation
  schema possible — a hand-drawn sprite can't be checked for a missing trait, a `BodyPlan` can.
- **Daintree tree-kangaroo corrected from Lumholtz's to Bennett's.** The brief names
  Lumholtz's tree-kangaroo for the tropical-north biome. Checked range: Lumholtz's
  (*Dendrolagus lumholtzi*) is concentrated on the Atherton Tablelands and reaches the
  Daintree River only as its *northern* limit; Bennett's (*D. bennettianus*) occupies the
  rainforest *north* of the Daintree River, which is the biome actually being built. Swapped
  to Bennett's; noted in `src/regions/australia/tropical.ts`.
- **Norway excludes muskox.** Despite being the animal most associated with the Dovrefjell
  plateau today, Norway's only wild herd was introduced from Greenland between 1932 and 1953
  after the mainland European population died out at the end of the last Ice Age. Not native,
  so left out, and the exclusion is documented in-pack (`excludedSpecies`) so it surfaces in
  `reference/SPECIES.md` as a decision rather than reading as an oversight.
- **Snow leopard's IUCN status (Vulnerable) is reported with its 2017 downlisting noted as
  contested.** Several sources flagged this as a disputed reclassification reflecting better
  counting rather than a real recovery; the Nepal pack's fact line says so rather than stating
  "Vulnerable" as settled.
- **Secretary bird listed as Endangered**, following the IUCN's current assessment; some
  older secondary sources still show the pre-2020 Least Concern / Vulnerable rating. Used the
  most recent reassessment.
- **Southern cassowary: Least Concern globally, Endangered nationally — both stated.** This is
  the clearest case in the whole species set of a national listing diverging from the global
  one; the `national` field exists in the schema specifically so this doesn't get flattened to
  one number that undersells the Australian population's situation.
- **Archey's frog (Aotearoa) documented but not one of the forest biome's five creature
  slots.** It is a Coromandel/Whareorino species and genuinely belongs in that forest biome,
  but there were six strong candidates for five slots; it is recorded as a near-miss in
  `aotearoa/index.ts`'s module comment rather than silently dropped or wedged into the wrong
  biome.
- **Creatures moved from procedural `BodyPlan` bodies to hand-authored `CreatureSprite`
  character grids, Memory Forest's own `web/visitors.js` technique — reversing the "art is
  entirely procedural" call above.** The procedural body-plan renderer was built because 140+
  species couldn't be hand-drawn to a consistent standard; in practice it produced creatures
  that read as generic shaded blobs rather than specific animals, which a hand-authored
  sprite — a handful of deliberately placed pixels, one or two signature marks per species —
  does not. `Creature.sprite?: CreatureSprite` is the new preferred field; `body`/`palette`
  stay on the type as the fallback `creatureSprite.ts` renders from when `sprite` is absent,
  so species not yet migrated keep working rather than silently losing their creature. Every
  creature across every region got a first-pass baked sprite (`src/regions/sprites/baked.
  generated.ts`, generated from the procedural generator itself — see `scripts/
  bakeCreatureSprites.ts`); 7 of Australia's got real hand-authored ones instead
  (`src/regions/sprites/handAuthored.ts`) — the 5 eucalypt-woodland species plus cassowary
  and platypus. `src/regions/index.ts`'s `withSprites` attaches whichever applies to each
  creature without any of the 11 region files needing an edit. Reviewed via `review/
  gallery.html` against Memory Forest's own fox/deer/owl; the user's `decisions.json` export
  (55 keep / 75 redo, mostly in the baked set) is what the still-open redo pass works from.
  The pack-validation point
  above ("a hand-drawn sprite can't be checked for a missing trait, a `BodyPlan` can") is a
  real loss for migrated species — `validate.ts` now checks a `CreatureSprite`'s palette hex
  values and frame-row shape, not whether its traits are visually represented, so that check
  is now what the gallery screenshot review is for.
- **Eucalypt woodland's two broadleaf eucalypt species got a new `sparse-broadleaf`
  `PlantForm`** rather than reusing the generic `broadleaf` crown every other rounded-canopy
  tree in every region shares. Real eucalypt crowns are characteristically open and clumped —
  visible gaps and branch structure, not a solid dome — which the existing `roundCrown`'s
  default hole/density settings didn't capture; `broadleaf` stays the dense-canopy default
  (figs, beeches, rainforest emergents) for every other species, migrated or not.
- **Phase 2: vendoring Memory Forest's rendering engine verbatim, on the `vendor` branch —
  a second reversal, this time of "no source file is copied verbatim" (see this file's
  Licensing section and `THIRD_PARTY_NOTICES.md`).** Explicit user decision, not a judgment
  call made here: after a long iterative polish phase on the procedural reimplementation
  kept missing the reference images on specific details, the user asked to adapt the
  original engine directly instead of re-deriving it. `reference/memory-forest/web/` copied
  unmodified into `src/vendor/memory-forest/web/`, `LICENSE` alongside it.
  - **Licence/edition check, done before copying anything:** this checkout has no
    `editions.json` — per `dev/editions.py`'s own comment ("the public repo has no
    editions.json: there, everything present is the edition"), that means this is the
    public/base-only snapshot. `settings/plus.json` and the `cherry_blossom`/`starry_night`
    PNGs present are locked-preview thumbnails for the settings picker UI, not the scenery
    code itself — that code was never included here. `manifest.json`'s `package` is
    `memory_forest` (the base `DEV_PACKAGE`, not `memory_forest_plus`). Confirmed nothing
    Plus-exclusive or differently licensed is in the tree; the whole thing is the one MIT
    licence already on file.
  - New work goes in new files that plug into the vendored engine's own registries (envs,
    landscapes, landmarks, tree hooks) rather than editing vendored files; an edit that's
    genuinely unavoidable gets marked `// Memory Grove change:` inline and listed here when
    it happens.
